# finance_bot — продуктовый обзор

**Статус:** MVP-решения зафиксированы (v3). Дальше — реализация по [REQUIREMENTS.md](REQUIREMENTS.md).

---

## 1. Что это

Telegram-бот учёта финансов для **любого числа пользователей** (регистрация из template). У каждого свой изолированный учёт.

- мультивалютные **счета** и операции;
- **импорт** выписок/таблиц → транзакции с категориями;
- **ручной ввод** и удаление;
- **статистика** за месяц или период;
- **месячный отчёт** текстом в Telegram (шаблон §5).

Интерфейс: Telegram + Django Admin. Логику из `finance_script/` переносим в бот, пакет скриптов не импортируем.

## 2. Зафиксированные решения (MVP)

| Тема | Решение |
|------|---------|
| Пользователи | Любое число; изоляция по `user`; sign_up из template |
| Семейный бюджет | Вне MVP |
| Язык UI | Только русский |
| Меню | См. §3 (статистика и отчёт раздельно) |
| Правка операции | В MVP нет: удалить → создать заново (или админка) |
| Импорт v1 | Сразу в БД + итог, без превью строк |
| Неизвестный формат | Сообщение об ошибке; ручная разметка колонок — позже |
| PDF Т-Банк | После базовых таблиц (xlsx/csv) |
| Счета | Обязательные сущности; при ручном вводе счёт обязателен |
| Валюты | Любые; операция в валюте счёта |
| Базовая валюта сводов | **USD** (в MVP не переключается) |
| Курсы | Автообновление **раз в час** из внешнего API; в отчёте — актуальный курс + метка времени |
| Категории | Базовый список + свои у пользователя (добавление/удаление своих; базовые можно скрыть у себя) |
| Структура категорий | Плоский список (имена вида «Подписки: IDE» допустимы) |
| Отчёт | Только текст; при открытии **пересобирается из БД** (всегда актуальный) |
| Ручное редактирование текста отчёта | Вне MVP; детализация = категории + описания операций |
| Рассылки | `mailing_bot` в compose есть, фичи в MVP нет |
| Админка | Для разработки и редких правок |
| Сайт | Не нужен |

## 3. Главное меню

```
┌─────────────────────────────┐
│  Добавить операцию          │
│  Удалить операцию           │
│  Импорт выписки / таблицы   │
│  Счета                      │
│  Категории                  │
│  Статистика                 │
│  Отчёт за месяц             │
└─────────────────────────────┘
```

### Сценарии

**A. Ручная запись** — счёт → доход/расход → сумма → категория → дата → комментарий.  
**B. Импорт** — файл → разбор → запись (дедуп) → итог.  
**C. Статистика** — месяц / период → итоги и категории (переводы отдельно).  
**D. Отчёт за месяц** — выбор месяца → текст по §5, собранный из текущих данных.

## 5. Формат месячного отчёта (текст)

Эталон — практика учёта + вывод `finance_script`.

```text
06.2026 отчет за июнь

=== Счёт: Тинек … ===
… категории, переводы, итого в ₽ и в $ …

=== Счёт: Credo USD (xlsx) ===
Период, валюта, сводка банка, пересчёт движений,
траты по категориям (%), внутренние переводы, доходы

итого: 2920$ (кредо) + 1435$ (тинек) = 4355$
курс на 27.07.2026 18:00 UTC (авто)
```

Правила:

1. Секция на каждый активный счёт / источник с данными за месяц.
2. Внутренние переводы не в «тратах».
3. Сводный итог трат в **USD**.
4. Длинный текст — несколькими сообщениями Telegram при необходимости.
5. Отчёт не «документ с ручной правкой»: источник истины — транзакции в БД.

## 6. Счета, валюты, курсы

- Счёт: название, валюта, банк/страна (опционально).
- Перевод между счетами — не расход.
- База отображения сводов: **USD**.
- Job раз в час тянет курсы (base=USD), пишет в БД.
- Пересчёт в отчётах/статистике: по **последнему успешно загруженному** курсу; внизу отчёта — время курса.
- Исторические курсы на дату операции — не в MVP (можно добавить позже, API это позволит).

Провайдер MVP: бесплатный hourly API без ключа (`https://api.exchangerate.fun/latest?base=USD` или аналог; вынести URL в `.env`). Fallback: не падать — оставить прошлые курсы и пометить в логе.

## 7. Категории

- **Базовые** — сид из практики `finance_script` (траты, доходы, «Внутренние переводы»).
- **Пользовательские** — полный CRUD у себя.
- Базовые глобально не удаляются; пользователь может **скрыть** базовую у себя.
- Список при вводе = видимые базовые + свои.
- Авто-категоризация по правилам (перенос из скриптов); неизвестное → «Прочие…» / ручной выбор позже.

## 8. Импорт

- Цель: произвольные таблицы; профили MyCredo / др. — ускорение.
- v1: xlsx/csv + эвристики заголовков; не распознали → ошибка с понятным текстом.
- PDF — отдельный этап после таблиц.

## 9. Вне скоупа MVP

- Смена базовой валюты пользователем
- Курсы «на дату операции»
- Выгрузка отчёта в файл
- Напоминания / mailing-фичи
